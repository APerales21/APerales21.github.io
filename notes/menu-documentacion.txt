Documentación de menu.html
==========================

Archivo: pages/menu.html
Ubicación de la documentación: notes/menu-documentacion.txt

NOTA DE RENOMBRADO (14/08/2026)
Esta página se llamaba pages/menu2.html y era la versión nueva del menú. Al quedar
terminada pasó a ser pages/menu.html, la página oficial de servicios. El menú anterior
se conservó como pages/menu-old.html. Esta documentación se llamaba
notes/menu2-documentacion.txt.

Consecuencia importante: menu.html es ahora el destino al que ya apuntaban index.html
(botón INICIAR) y los enlaces de regreso de celulares, consolas y mantenimiento, así que
quedó integrada en la navegación sin tocar esos archivos.

1. Propósito general
-------------------
Página oficial de servicios del sitio. Diseño neo-brutalista (bordes negros de 3px, sombras
duras de 12px, paleta salmón/durazno) con sistema de tema claro/oscuro. Muestra tarjetas de
servicios enlazadas a otras páginas, secciones de presentación, reseñas y contacto, y un pie
de página con los datos del negocio.

2. Estructura principal
-----------------------
La página está organizada en estas secciones:

- Header (fijo):
  - Botón de regreso a index.html.
  - Título principal: TAPIR INDUSTRIES.
  - Botón para alternar entre modo claro y oscuro.

- Sección de servicios:
  - Rejilla de 6 tarjetas. Cada una es un enlace a otra página o a un marcador vacío.
  - Los servicios mostrados son:
    - Mantenimiento    -> pages/mantenimiento.html
    - Reparaciones     -> pages/celulares.html
    - Controles        -> pages/consolas.html
    - Impresoras       -> pages/impresoras.html
    - Diseño gráfico   -> pages/diseno.html
    - Desarrollo móvil y web -> pages/desarrollo.html

- Sección "Nosotros" (id="nosotros"):
  - Texto de presentación, tres fortalezas destacadas y un botón "Conoce al equipo"
    que lleva a pages/fundadores.html.

- Sección "Reseñas" (id="resenas"):
  - Tres tarjetas de opinión. Cada una lleva estrella + calificación 5/5 y el sello
    "Reseña de Facebook". Las opiniones provienen de la página de Facebook del negocio.

- Sección "Contacto" (id="contacto"):
  - Chips de contacto: WhatsApp, correo, Facebook e Instagram.

- Asistente visual (mini-tapir-widget):
  - Sprite animado fijo abajo a la izquierda que muestra mensajes rotativos.

- Footer:
  - Servicio a domicilio, ubicaciones, WhatsApp, correo, horario y disponibilidad.

3. Estilos y tema visual
------------------------
El archivo incluye estilos inline en la etiqueta head y también estilos adicionales para el footer y las tarjetas.

Puntos importantes:
- Usa variables CSS como --bg, --text, --card, --accent, --muted, --glass y --transition.
- El modo claro y oscuro se activan mediante el atributo data-theme en el elemento html.
- El color del fondo cambia según el tema:
  - Claro: usa la imagen day.gif como fondo.
  - Oscuro: usa la imagen not.gif como fondo.
- La cabecera, las tarjetas y el footer adaptan colores según el tema.

4. Modo claro/oscuro
--------------------
El tema se controla con JavaScript y con el atributo data-theme.

Comportamiento:
- Al cargar la página, se intenta aplicar un tema inicial basado en:
  1. Preferencia guardada en localStorage.
  2. Preferencia del sistema.
  3. Modo claro como valor por defecto.
- También existe una función que intenta establecer el tema según la hora del día:
  - Entre las 7:00 y las 17:59 se usa light.
  - Entre las 18:00 y las 6:59 se usa dark.
- El botón con id themeToggle alterna el tema manualmente.
- El texto del botón se actualiza según el estado actual.

5. Animación del canvas
-----------------------
Se incluye un canvas con id exa en la parte inferior de la página.

Función:
- Dibuja hexágonos animados con colores naranja/rojo/amarillo.
- Añade puntos girando alrededor del centro.
- La animación se ejecuta con requestAnimationFrame.

Importante para cambios futuros:
- Si se modifica el canvas o el estilo, conviene mantener el id exa y el contexto 2D del canvas.
- El fondo blur del canvas y el z-index 0 ayudan a que no interfiera con el contenido principal.

6. Scripts incluidos
--------------------
El archivo carga varios scripts inline y uno externo:

- Script externo:
  - https://unpkg.com/lucide@1.29.0/dist/umd/lucide.min.js (build UMD de Lucide)
    Seguido de una llamada inline a lucide.createIcons(), que reemplaza cada
    <i data-lucide="..."> por su <svg> conservando las clases CSS.

    IMPORTANTE: antes esta pagina cargaba ../src/main.js como modulo. No funcionaba
    en produccion porque src/main.js hace "import ... from 'lucide'" (especificador
    bare) y GitHub Pages sirve la raiz del repositorio tal cual, sin pasar por Vite;
    el navegador no puede resolver ese import y ningun icono se dibujaba. El build UMD
    funciona igual servido como archivo estatico y con "npm run dev".
    Si se cambia la version del CDN, debe coincidir con la de package.json.

- Scripts inline:
  - Lógica de tema claro/oscuro.
  - Animación del canvas.
  - Script de arrastre o desplazamiento horizontal para una fila de tarjetas (actualmente no aplica a la estructura HTML presente).
  - Script de protección contra inspección del código (DevTools), que:
    - Bloquea F12, Ctrl+Shift+I, Ctrl+U y clic derecho.
    - Reemplaza el contenido del body con una pantalla de error si se detecta actividad sospechosa.
    - Detecta cambios de tamaño de ventana que puedan indicar DevTools abiertos.

7. Consideraciones importantes para futuras modificaciones
--------------------------------------------------------
- No cambiar los IDs themeToggle y toggleLabel si se quiere conservar la lógica del tema.
- Si se agregan o cambian tarjetas de servicio, mantener la clase service-card-link para conservar el estilo visual.
- Si se cambian los enlaces de las tarjetas, revisar que las rutas relativas sigan siendo correctas.
- Si se modifica el diseño del header o del footer, tener en cuenta que utilizan variables CSS y estilos dependientes del atributo data-theme.
- Si se eliminan o cambian los elementos con clases como service-card-link, head, content, footer-panel, etc., se pueden romper estilos visuales ya definidos.
- En las tarjetas de reseña, la regla genérica .review-card span aplica display:block y un color
  propio a TODOS los <span> de la tarjeta. La estrella y el "5/5" dependen de que
  .review-stars span le gane en especificidad. Si se reordena o se mueve ese CSS, revisarlo.
- Los iconos se generan en tiempo de ejecución: en el HTML son <i data-lucide="..."> y Lucide
  los convierte en <svg> conservando el atributo class, pero descartando title. Por eso los
  estilos deben apuntar a la clase, nunca a la etiqueta <i>.
